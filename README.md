# 💤 LazyVim

A starter template for [LazyVim](https://github.com/LazyVim/LazyVim).
Refer to the [documentation](https://lazyvim.github.io/installation) to get started.

## 中文稿件润色

在原稿按 `<leader>aw`，新开一轮 CodeCompanion 五步润色。
普通模式读取光标所在的连续非空段落；可视模式读取字符或整行选区，不支持块选区。

流程为「原文分析 → 八类视角 → 推荐写作书籍与原则 → 确认目标与方案 → 定稿」。
提示词尽量沿用 Cherry 的「中文润色专家」，保留角色设定、视角本体说明、方向词汇累计与五步交互。
角色与各步指令只在后台发送，不作为聊天正文显示；每步完成后只预填对应的输入栏。
第一步自动发送，随后等待用户在输入栏下方的新行填写，再手动发送。
补充或提问留在当前步骤，不按回复次数推进。
第一至第三步没有补充时填「无」，也可单独填「继续」或「确认」推进。
输入栏未填写时拒绝提交，不会提前进入下一步。
第四步先填写方案，模型完整回显四项选择后，再单独填「确认」进入定稿。
也可明确写「采用默认方案」，采用已展示的默认组合；「无」不能代替方案选择。
分析、视角和书籍建议使用 Markdown 标题与列表，不再整段放进代码块。
本工作流不叠加默认编程助手的系统提示词，其他聊天不受影响。
单段模式的每个新段落须从原稿重新按 `<leader>aw`，不沿用上一轮偏好。

### 连续分段

长稿可按 `<leader>aW` 启动连续分段：普通模式处理整个 buffer，可视模式只处理选区。
只排入按空行分开的普通正文，保留段内软换行，不按字数切断句子。
支持纯文本、Markdown、Quarto 及 Markdown 类文件类型。
Markdown 语法由 Tree-sitter 识别，标题、YAML、代码、表格、列表、引用块和独立公式等不参与润色。
Quarto div 分隔符受保护，内部普通正文仍可处理。
parser 不可用、没有正文或文件格式不受支持时拒绝启动，不冒险按空行处理结构内容。
可视模式的首尾可只选半段，修改与相邻上下文都不越出选区。

首段自动进入五步流程，确认的字数是每段目标，不是全篇总字数。
后续各段复用已确认方案，直接进入定稿；确认方案前跳过首段，下一段仍走五步。
每段新开独立聊天，只携带当前段和前后各一个只读正文段，不累积此前所有对话。
前段已采用时使用采用后的文本，跳过时保留原文；失效的相邻段不会作为新上下文发送。
已发送的相邻上下文若后来改变，本段停止发送与采用，须跳过或停止后重开，不改写历史消息。

批次聊天显示当前段号、总段数及采用／跳过数量，并提供以下局部命令：

- `<leader>aA`／`:ChinesePolishApply`：确认采用当前段，不自动保存或请求下一段。
- `:ChinesePolishNext`：采用或跳过后预览下一段，填写「开始」或本段要求，再手动发送。
- `:ChinesePolishSkip`：确认后保留原文并跳过，不请求下一段。
- `:ChinesePolishPlan`：回到第四步修改共享方案，完整回显并再次确认后用于本段及后续段。
- `:ChinesePolishStop`：停止批次及排队请求，保留此前已经采用的修改。

普通输入的修改要求只作用于本段，不自动改为全篇偏好。
请求运行时须先取消，才能跳过或修改方案；网络失败不推进段号，允许手动重试。
原稿范围已修改或失去正文结构时拒绝覆盖，可跳过或停止后重新启动。
同一原稿只能有一个分段批次，不同 buffer 可以独立处理。
关闭或清空当前活动聊天、关闭原稿会结束批次，隐藏窗口不会。
关闭已处理的旧聊天不影响当前段；恢复历史不恢复队列或写回权限。
队列只在本次 Neovim 进程中保留，不提供跨会话续跑。

### 定稿与显示

定稿保留在聊天中，不会自动修改原稿。
在本轮聊天按 `<leader>aA` 或执行 `:ChinesePolishApply`，确认后才替换启动时的原稿范围。
原稿范围已修改、引文标记有变化或定稿不完整时，拒绝覆盖。
定稿须有唯一、完整、非空且至少四个反引号的 `polished` 围栏。
格式或引文检查失败时，同一模型最多自动修复两次，仍不通过则等待手动修改。
自动修复不会验证事实、数字口径或因果关系，也不会自动采用定稿。
网络失败不自动重试；取消、清空、关闭聊天或原稿失效后，不再发出排队中的修复请求。
写回不会保存文件，可回到原稿按 `u` 撤销。
已恢复的历史聊天不提供写回入口，请重新启动工作流。

工作流固定使用 DeepSeek V4.1 Flash（`deepseek-flash`），密钥由
`~/.private_info.sh deepseek` 在运行时查询，不写入配置。
第三步直接依据模型已有知识推荐书籍与写作原则，不联网搜索、不下载或重读书籍。
本工作流不加载工具，也不需要 `TAVILY_API_KEY`；其他聊天的工具配置不变。
书名或作者拿不准时不推荐，允许只选写作原则、不选书籍，不编造书中原文与页码。
原稿会发送给 DeepSeek。
程序检查引文标记和原稿范围，不代替作者核对事实与修改质量。

提示词和阶段控制／写回逻辑分别位于 `prompts/chinese_polish.md`、`prompts/chinese_polish.lua`。
Lua 入口复用 CodeCompanion 原生条件订阅与重复执行，Markdown 模板不重复注册菜单项。
现有 `<A-o>` 润色入口与默认聊天模型不变。

聊天折行改用 `mdwrap.nvim` 的显示预览，通过 `render-markdown.nvim` 的渲染回调接入。
显示设置位于 `lua/plugins/markdown.lua`，使用 `wrap_sentence=true` 按宽填行，
宽度取窗口正文区与 `max_width=120` 列的较小值。
普通模式下显示预览，插入与可视模式下恢复原生显示。
`:MdwrapDisplay toggle` 可切换当前缓冲区的显示折行。
这套预览不插入真实换行，也不改变空格、原稿、用户输入或发送给模型的消息。
已移除回复完成后的硬折行、折叠行号补偿，以及聊天缓冲区的 Conform `mdwrap` 配置。
`Reasoning` 折叠继续由 CodeCompanion 原生管理。
代码块（包括 `polished` 定稿）与表格不注入预览断点，原有引文与中文引号渲染保留。
流式输出与输入窗口保留 `wrap=true`、`linebreak=false`，其他 Markdown 的硬折行设置不变。

## 中文引号显示

在现有 Markdown 渲染范围内（包括 CodeCompanion 聊天），成对的 `「」`、`『』`、`“”`、`‘’` 隐藏，
内部文字以 `RenderMarkdownChineseQuote` 高亮，默认跟随配色方案的 `Special` 颜色。
支持嵌套与同一段内的跨行引号；未配对引号、代码和链接地址不处理，英文直引号与书名号不变。
这只改变显示，不删除正文中的引号，也不改变发送给模型的消息。
使用 `:RenderMarkdown toggle` 可连同其他 Markdown 装饰一起关闭或恢复。
实现位于 `lua/lbs/markdown/quotes.lua`，通过 `lua/plugins/markdown.lua` 接入渲染器。

## 历史标题兼容

`lua/lbs/codecompanion/history.lua` 为当前锁定的历史扩展版本提供兼容修复。
标题上下文在消息副本上按 UTF-8 字符边界限长，避免截断中文或 emoji，不改原稿及聊天记录。
标题请求改用原生异步后台接口，HTTP 错误会正常回调，不再把错误表直接拼接成字符串。
自动标题、历史保存与浏览仍保持开启；更新历史扩展后需复核这层兼容逻辑。
